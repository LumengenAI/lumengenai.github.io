## 1. 定位与目标

网站定位为**个人主页 + 持续生长的技术知识库**。它同时回答：Henry Xing 是谁、研究什么、读者从哪里开始阅读或学习。

面向三类读者：合作方快速了解背景与代表作；技术同行按领域查找文章；学习者按顺序完成课程。作者则以 Markdown + Git 更新，不必每次修改模板。

首版成功标准：

- 首页首屏展示姓名、准确的个人定位和技术方向。
- 专题、笔记、课程、关于四个入口可达，桌面与手机布局完整。
- 新增笔记只需提交一个 Markdown 文件；课程顺序由作者明确控制。
- 文章有稳定链接、摘要、日期和归属专题；RSS 与 sitemap 可用。
- 手机端无页面横向滚动；Lighthouse 移动端性能及可访问性各以 90 分以上为目标。

首版不做 CMS、账户、站内搜索、评论、复杂动效、多语言或自建 CI。内容不足时不展示空栏目，不虚构经历、课程或项目。

## 2. 信息架构

| 路径 | 页面 | 主要内容 |
|---|---|---|
| `/` | 首页 | 个人定位、四个专题、精选内容、最近更新、简短介绍 |
| `/topics/` | 专题总览 | 四个领域的概述和入口 |
| `/topics/video-codec/` | 视频编解码 | 领域简介、推荐起点、相关笔记和课程 |
| `/topics/aigc/` | AIGC | 同上 |
| `/topics/computer-graphics/` | 计算机图形学 | 同上 |
| `/topics/cloud-native/` | 云原生技术 | 同上 |
| `/notes/` | 技术笔记 | 按日期倒序，按专题浏览 |
| `/notes/<slug>/` | 笔记详情 | 正文、相关内容、修订日期 |
| `/courses/` | 课程 | 课程目录、适用对象和章节数 |
| `/courses/<slug>/` | 单门课程 | 简介、先修知识、按顺序排列的课时与资源 |
| `/about/` | 关于 | 背景、代表项目、授课经历、兴趣爱好、联系方式 |
| `/feed.xml`、`/sitemap.xml` | 订阅与索引 | 自动生成 |
| `/404.html` | 未找到页面 | 返回主要入口 |

文章 URL 不包含日期，方便后续修订；slug 用简短英文小写和连字符，发布后不随意更改。迁移旧文时须保留旧地址或安排重定向。

主导航：**站名（首页）｜专题｜笔记｜课程｜关于**。GitHub、RSS 和邮箱放在页脚；首页另有 GitHub 入口。项目首版进入首页精选和关于页，积累至少 5 个、需要独立案例时再考虑 `/projects/`。兴趣先放在关于页，持续写作后再升级为栏目。

最近更新
日期         标题                               专题 · 类型

首屏以姓名、定位及技术方向为主，不用巨大的欢迎语、装饰插画或整屏空白。桌面与手机首屏均应露出下一段内容。精选内容手工维护，最近更新自动生成。

### 专题页

页首说明领域覆盖范围，并给出“从这里开始”的阅读入口。下面按“推荐阅读 / 相关笔记 / 相关课程”排列，不把所有内容混成时间流。四个专题共用一个页面结构；隐藏没有内容的分区。

### 笔记页与详情

列表项包含日期、标题、1 到 2 行摘要、专题和内容形式。默认倒序；首版通过专题页浏览，不引入前端过滤器。正文注重标题层级、代码块、图表说明和外链；文末可放相关内容及更新日期。

### 课程页

列表显示名称、受众、先修要求和简介。单门课程按教学顺序组织章节与课时，附视频、讲义、代码仓库等已有资源；没有的资源不显示占位按钮。课程顺序不依赖文章日期。

### 关于页

按“简介 → 关注方向 → 代表项目/经历 → 授课 → 兴趣爱好 → 联系方式”组织。介绍具体成果和可核实链接，避免简历式长墙。邮箱与 CV 下载是否公开由作者确认。

## 4. 内容模型与维护

**专题是讨论领域，形式是内容呈现方式。** 同属视频编解码的排查笔记和编码原理教程，不应被迫归为同一内容形式。

笔记使用 Jekyll `_posts/`，显式 permalink 保持 `/notes/<slug>/`：

```yaml
---
layout: post
title: "文章标题"
date: 2026-11-25 10:00:00 +0800
permalink: /notes/example-slug/
description: "一到两句摘要"
topic: video-codec
type: note
updated: 2026-11-25
---
```

`topic` 首版取 `video-codec`、`aigc`、`computer-graphics`、`cloud-native` 之一；跨领域文章选主要专题，必要时添加少量 `tags`，首版不生成标签页。`type` 取 `note`、`tutorial`、`case-study`，但不作为主导航。文件名仍遵循 Jekyll 的 `YYYY-MM-DD-english-slug.md`。重要修订更新 `updated`，不通过改发布日期把旧文推成新文。

四个专题页是固定 Markdown 页面，由模板按 `topic` 聚合笔记。课程首版用课程列表和逐门课程的 Markdown 页面，课时链接笔记、视频、PDF 或仓库；课程多起来再迁移为 Jekyll collection。关于页、精选项目和兴趣内容先手工维护。

**首发内容建议**：经本人核实的定位、完整的关于页、2 篇真实笔记、1 门真实课程的目录。尚未公开课程时，课程入口可保留，但列表清楚说明筹备状态，不展示虚构课时；如果准备长期没有课程，则暂不显示该导航入口。每个专题至少有一段真实简介，首页精选最多 3 项。

日常流程：新增 Markdown → 填 front matter → 检查链接和图片 → 提交推送 → 在线确认页面与 RSS。每季度检查首页精选、失效外链和课程资源。图片放在 `assets/images/`，优先 WebP、添加明确 alt；视频优先外链或按需加载嵌入，避免拖慢首页。

## 5. 视觉规范

方向：**清晰、克制的技术编辑风格**。以内容、排版和细线建立层级，不堆浮动卡片、渐变、3D 或装饰性大图。

| 元素 | 首版规范 |
|---|---|
| 背景 / 正文 | 浅灰白 `#F8FAF9` / 深灰 `#202826` |
| 主强调色 | 深青绿 `#146C61` 用于链接与当前导航；低饱和橙 `#B45D31` 可用于课程或精选 |
| 分隔线 | `#D8DFDB`；列表以细线分组，不层层套卡片 |
| 字体 | 系统中文字体栈，代码用系统等宽字体；无远程字体 |
| 字号 | 正文 16px、行高约 1.7；首页姓名 36–44px，页标题 28–32px，小节标题 21–24px |
| 宽度 | 主布局最大约 1100px，正文最大 720px；代码块可独立横向滚动 |
| 间距 | 8px 基础节奏；用留白区分标题、列表和分区，避免过度稀疏 |

桌面首页可适当组合左右布局，阅读页以单栏为主。小于约 720px 时统一单栏，专题入口变两列或一列；导航允许换行，保证触达面积，不强制汉堡菜单。文本不能与按钮或相邻内容重叠。

使用语义化 HTML、`lang="zh-CN"`、可见焦点、跳转正文链接、图片 alt 和足够的色彩对比。暗色模式在首版内容与配色验收后再做。

## 6. 技术边界

保留 GitHub Pages 原生 Jekyll 构建，不引入 Node 构建或 GitHub Actions。`_config.yml` 负责站点元数据、permalink、SEO、RSS、sitemap，排除 `README.md` 与 `docs/`；只使用 GitHub Pages 支持的插件。

仓库当前只配置了 `jekyll-theme-minimal`，它不足以承载上述首页、专题和课程。实施时需要少量自有 `_layouts/`、`_includes/` 和 CSS/SCSS；不假设仅换主题配置就能完成。模板保持精简。部署源采用 `main` 根目录。没有本地 Ruby 时仍可写作和推送，但模板改动应在线确认构建日志与页面。

## 7. 阶段与验收

1. **骨架**：配置、共享布局、首页、专题总览及四个专题页、笔记列表、课程列表、关于、404，确认手机与桌面布局。
2. **真实内容**：作者核实简介、公开联系方式、代表项目和首批笔记/课程；不发布“示例文章”充数。
3. **打磨**：SEO/OG 图片、RSS、sitemap、相关内容、性能及可访问性检查；按实际阅读效果调整排版。
4. **按需扩展**：课程多了再使用 collection；文章多了再考虑搜索；评论、统计和多语言分别评估。

验收逐一检查首页、导航、专题、一篇笔记、一门课程目录、404、RSS 与 sitemap。新增笔记后应自动出现在笔记列表、对应专题、首页最近更新和 RSS 中；课程顺序仍由作者设定。手机宽度无页面横向滚动，代码块可独立滚动。

## 8. 需要作者确认

1. 首页的一句话定位及可公开的工作经历，不能由模板代写。
2. 四个专题名称和第一批公开笔记的归属。
3. 首门课程的名称、受众、章节、已有视频/讲义/代码链接。
4. 邮箱、社交账号、头像、CV 下载的公开范围；是否计划使用自定义域名。

这些信息不阻碍搭建结构，但决定首版实际显示哪些模块。
